# SovRing-Labs

[![status: pre-alpha (under development)](https://img.shields.io/badge/status-pre--alpha%20%28under%20development%29-orange)](STATUS.md) **Status: pre-alpha, under development** — interfaces, numbers and file layout can change without notice; [STATUS.md](STATUS.md) says what works today.

[![defensive publication: every repository](https://img.shields.io/badge/defensive%20publication-every%20repository-blue)](STATUS.md) **Defensive publication:** each repository's `TECHNICAL-DISCLOSURE.md` is dated prior art; DOIs (Zenodo) are in [STATUS.md](STATUS.md).

**AI that runs on the computers people already own — capable, reliable and checkable.**

SovRing-Labs is an open research lab. Its core idea is the *residue ring*: numbers and memories kept as remainders on several
small prime rings. That makes some arithmetic exact and independent of order, and lets a memory be found by its address instead
of by searching. Around that core sit the tools that run a fleet of AI coding agents safely and cheaply, a from-scratch web
engine, and the research papers together with the scripts that produced every number in them.

Every repository below has a **quick test** you can run in minutes, and every claim it makes has a test you can re-run yourself.

## Try it — pick one

**1. Paste this to your coding assistant** (Claude Code, Cursor, opencode, Copilot, …):

> Read https://github.com/SovRing-Labs/SovRing — start with its `llms.txt` — then help me pick one repository, set it up
> and run its quick test. Explain what the test proves.

**2. Connect the MCP server** (the assistant can then explain, check your machine, clone and run tests by itself):

```bash
git clone --depth 1 https://github.com/SovRing-Labs/SovRing ~/sovring/SovRing
claude mcp add sovring -- python3 ~/sovring/SovRing/.mcp/server.py     # Claude Code; Cursor/opencode: .mcp/README.md
```
Then ask: *"Use the sovring tools: explain, check my readiness, and run the armilla-astrolabe quick test."*
No install at all: `https://gitmcp.io/SovRing-Labs/SovRing` is a read-only docs endpoint for any MCP client.

**3. Three commands yourself:**

```bash
git clone --depth 1 https://github.com/SovRing-Labs/SovRing && cd SovRing
./install.sh --list                       # the repositories, what each needs, its quick test
./install.sh armilla-astrolabe            # clone into ~/sovring, install deps, run the quick test
```
Clones go to `~/sovring`; set `SOVRING_HOME=/some/dir` to put them elsewhere (the MCP server uses the same variable).

## Re-check every claim — one file

[`sovring-suite.pyz`](https://github.com/SovRing-Labs/SovRing/releases/latest/download/sovring-suite.pyz) is a release asset
of this repository: one file, Python standard library only (python3 >= 3.8), carrying every repository's `suite.json`.

```bash
python3 sovring-suite.pyz --list                 # every repository and test, and what can run on this machine
python3 sovring-suite.pyz --fetch armilla-astrolabe && python3 sovring-suite.pyz --run armilla-astrolabe
python3 sovring-suite.pyz                        # a local page on 127.0.0.1: claim, expected value, evidence, run button
```
Each repository also carries `bash install.sh` (the same suite, run from inside that checkout).

Honest status of each repository — what works today, what is not yet tested, known failures, corrections — is in
[STATUS.md](STATUS.md). More detail: [QUICKSTART.md](QUICKSTART.md) (5 minutes) · [llms.txt](llms.txt) (for assistants) ·
each repository's `AGENTS.md`, `STATUS.md` and `DOSSIER.md` (armilla-astrolabe: `TECHNICAL-DISCLOSURE.md`). Each repository
carries its own `suite.json`; copies of all twelve are in [suites/](suites) and inside `sovring-suite.pyz`.
